What We've Built

Complete feature inventory as of June 2026

Scraper

  • Rightmove search via __NEXT_DATA__ JSON (Next.js page — no HTML parsing needed)
  • Deduplicates by listing URL; re-scrapes update date_listed and available_from for existing listings
  • Weekly prices auto-detected via price.frequency == "weekly" and multiplied by 4.3 for PCM equivalent
  • Uses listingUpdate.listingUpdateDate for "listed date" — not firstVisibleDate, which reflects original creation and can be years old for re-listed properties
  • Move-in date: prefers letAvailableDate from search JSON; daily fallback fetches individual listing pages and extracts from <dt>Let available date</dt>

Travel time calculator

  • TfL Journey Planner API: 12 calls per listing (3 destinations × 4 modes)
  • 5 listings processed in parallel; all 12 calls within each listing also run concurrently
  • Global rate limiter at 7 calls/sec across all threads (safely under 500/min TfL cap)
  • If transit_no_bus returns null, falls back to transit_all for the 30-min threshold check (some areas are bus-only)
  • Listings where all transit values are null (TfL glitch) have their rows cleared each scrape and are automatically retried

Dashboard (/)

  • Card grid, 30 per page with pagination
  • Default sort: Best match (composite score — see Scoring below)
  • Also sortable by: best commute, cheapest first
  • Status filter: hide rejected / my shortlist / everyone shortlisted (consensus)
  • Header stats: N listings match · N commute · N too late · N calculating
  • Per-card: photo, price/beds/area, listed-N-days-ago, available-from (green if ideal window, amber if later), full 3×4 travel time table, Shortlist / Reject / View buttons
  • Travel time pills: green (<20 min) / amber (20–30) / red (>30)
  • Green "New" badge on photo for listings listed ≤ 2 days ago
  • Vote summary row on each card — shows each flatmate's status (✓ shortlisted / ✗ rejected / · undecided)
  • Collapsible comment thread on each card — shows existing comments, text input to add one
  • Name picker modal on first visit — stores name in localStorage + cookie (no login required)
  • Shortlist/reject buttons are per-user; card border reflects your own vote

Map (/map)

  • Leaflet.js, no API key, all JS from CDN
  • Theme 2 (default): light Carto tiles, circle pins with coloured ring, star-in-circle for shortlisted, navy pill destination labels
  • Theme 7 (Disco ✦): dark no-labels tiles, iridescent oval pins with unique gradient per listing, 8-pointed starburst for shortlisted, glowing text destination labels. Toggle via "✦ Disco" button in nav.
  • Click any pin → rich popup: photo, price, beds, available-from, full 3×4 commute table, vote summary, last 2 comments, Shortlist/Reject/View buttons
  • Shortlisting from popup immediately swaps the pin to a star (no reload)
  • Layer toggles: all qualifying / my shortlist / include rejected
  • Marker clustering — zooms out to numbered bubbles
  • Destination markers (MATS, LISA, KX) with tooltip showing full address

Scoring algorithm

Lower = better. Used for "Best match" sort.

score = (worst_work_commute × 2)
      + ((price_pcm - 2500) / 800 × 8)
      + 15 if bedrooms < 3
      + 0–10 availability penalty (linear, ideal→cutoff window)
ComponentWeightEquivalent
Commute (worst of MATS/LISA, transit)×2 per minute20-min commute = 40 pts
Price (normalised £2,500–£3,300)×8 across range£3,300 vs £2,500 = 8 pts
2-bed penaltyflat +15≈ 7.5 extra commute minutes
Availability penalty0–10 linear≈ up to 5 extra commute minutes

Data model

listings

ColumnNotes
urlUnique dedup key — rightmove.co.uk/properties/{id}
price_pcmAlways monthly; weekly prices converted on ingest
lat / lonFrom Rightmove's location field; postcodes.io fallback
date_listedFrom listingUpdate.listingUpdateDate (agent's "Added on" date)
available_fromFrom letAvailableDate or daily page scrape; null = unknown
statusnew / shortlisted / rejected — legacy global field; per-user votes now in votes table
is_removed1 if Rightmove page shows "removed by agent"

travel_times

One row per (listing_id, destination, mode) — 12 rows per listing. duration_minutes is null if TfL returned no route.

votes

One row per (listing_id, user_name). Primary key is the pair. status: shortlisted / rejected / new. Updated via POST /vote/<id>.

comments

Free-text comments. Multiple per person per listing. Added via POST /comment/<id>. Read via GET /comments/<id>.
