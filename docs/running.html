Running & Configuring

Setup, running locally, and tuning search parameters

First-time setup

# 1. Create and activate the conda env
conda create -n london_flat_hunting python=3.12 -y
conda activate london_flat_hunting

# 2. Install dependencies
pip install -r requirements.txt

# 3. Create .env with your TfL API key
echo "TFL_API_KEY=your_key_here" > .env

To get a TfL API key: register at api-portal.tfl.gov.uk, subscribe to any product, and copy the Primary Key from your Profile page.

Running the app

conda activate london_flat_hunting
python main.py

Flask starts immediately at http://localhost:5000. The scraper and travel time calculator run as background threads — you don't need to wait for them.

What happens on first run

  1. DB is created at data/listings.db if it doesn't exist
  2. Scraper fetches Rightmove in the background (~3 min for ~1,000 listings)
  3. Travel time calculator works through listings in parallel (~20–25 min for full batch)
  4. Dashboard shows qualifying listings as they complete — refresh to see more appearing
  5. Daily check runs after 24 hrs to catch removals and fill missing available-from dates
The "N calculating" counter in the dashboard header shows how many listings are still waiting for travel times. This will count down to 0 over the first 20–25 minutes.

Config knobs (config.py)

VariableDefaultWhat it changes
MAX_COMMUTE_MINUTES30Hard commute cutoff — listings above this are filtered entirely
AVAIL_IDEAL_DAYS12Days from today = ideal move-in window (no score penalty)
AVAIL_CUTOFF_DAYS49Days from today = hard availability cutoff (filtered out if later)
SCRAPE_INTERVAL_MINUTES60How often to check Rightmove for new listings
SEARCH.min_price2500Minimum monthly rent (£)
SEARCH.max_price3300Maximum monthly rent (£)
SEARCH.min_bedrooms2Minimum bedrooms
Availability thresholds are relative to today, not hardcoded dates. If you're still hunting in 3 weeks, the same offsets apply — no config change needed.

Changing commute destinations

Edit the DESTINATIONS dict in config.py. Each entry has lat, lon, short (map label), and depart_time (HHMM string).

Useful admin commands

# Run daily check immediately (fill missing dates, mark removed)
conda activate london_flat_hunting
python3 -c "from scraper.rightmove import daily_listing_check; daily_listing_check()"

# Check DB state
python3 -c "
from db.database import get_conn
c = get_conn()
print('Listings:', c.execute('SELECT COUNT(*) FROM listings').fetchone()[0])
print('With times:', c.execute('SELECT COUNT(DISTINCT listing_id) FROM travel_times').fetchone()[0])
print('Removed:', c.execute('SELECT COUNT(*) FROM listings WHERE is_removed=1').fetchone()[0])
"

# Force re-run travel times for all listings (clears and recalculates)
python3 -c "
from db.database import get_conn
get_conn().execute('DELETE FROM travel_times')
"
# Then restart the app — it will recalculate everything
